Figure 3. Panneau A, lock par repository : l'agent A (branche x) écrit, l'agent B (branche y) attend la fin de A, puis écrit ; l'écriture se termine quand le replica le plus lent répond. Panneau B, lock par ref : A et B écrivent en parallèle ; seuls deux agents sur la même branche s'attendent. Repères rapportés par GitHub : 5 replicas par défaut ; environ 25 ms d'aller-retour vers Azure ; plusieurs allers-retours par écriture ; 3 à 4 fois plus de débit pour des écritures vers des refs différentes (tests internes de GitHub, montage non publié). Encadré « Exemple pédagogique, pas un chiffre de GitHub » : 40 ms de travail plus 3 allers-retours de 25 ms font 40 + 75 = 115 ms sous lock, soit 1000 / 115 ≈ 9 écritures par seconde ; sans attente réseau, 1000 / 40 = 25 écritures par seconde.
